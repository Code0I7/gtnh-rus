## Реализация

Перевод выполнен языковой моделью **Claude Opus 5** итерациями по смысловым блокам.
Относительно исходного пака изменено 7 295 строк в 92 файлах.

Перевод может содержать ошибки в терминах, падежах и трактовке игровых механик.
Описанная ниже проверка строгая, но она проверяет **сохранность формата**,
а не оригинальный смысл.

### Автоматическая проверка

Перед записью каждой партии и после неё сверялось:

- количество строк в файле не изменилось;
- ключи не изменились и не переставлены;
- комментарии и пустые строки на месте;
- совпадают счётчики `%s`, `%d`, `%b`, `%%`, `%1$s`, `%,d`, `%.3f`, `%c`;
- совпадает число цветовых кодов `§`;
- совпадают литеральные `\n`, `<BR>`, `<LINE>`, `%n`;
- сохранены значимые ведущие и концевые пробелы;
- нет символов `CR` и `BOM`.

Партия применялась целиком или не применялась вовсе: одна непрошедшая
строка отменяла весь заход. Ни одна правка не принята при ненулевом числе
расхождений.

### Что сверялось с кодом модов

Часть решений принята по содержимому .jar сборки:

| решение | источник |
|---|---|
| палитра цветов тиров | `GTValues.TIER_COLORS` |
| цвета примарных аспектов | поле `chatcolor` в `Aspect.class` |
| поведение поиска NEI | `ItemList$PatternItemFilter.matches()` |
| английские оригиналы строк | `GregTech.lang` инстанса, `assets/<mod>/lang/en_US.lang` |
| порядок размеров мультиблоков | сверка по ключам с `GregTech.lang` |

Отдельно проверено, что **цветовые коды не мешают поиску**: в NEI имя
предмета прогоняется через `EnumChatFormatting.getTextWithoutFormattingCodes()`
до сопоставления, ванильный поиск в творческом режиме делает то же самое.

## Соглашения перевода

### Тир предмета

До правок в паке одновременно жили три записи тира:

```
LV Корпус механизма
Геологический сканер (LuV)
Камнерез LV
```

Приведено к одному виду — квадратные скобки, в конце имени, цветом мода:

```
Корпус механизма §2[LV]§r
Геологический сканер §d[LuV]§r
Камнерез §2[LV]§r
```

Цвета взяты из `GTValues.TIER_COLORS` сборки:

| тир | код | тир | код |
|---|---|---|---|
| Пар | `§f` | ZPM | `§b` |
| ULV | `§c` | UV | `§2§n` |
| LV | `§2` | UHV | `§4§n` |
| MV | `§6` | UEV | `§5§n` |
| HV | `§e` | UIV | `§1§l§n` |
| EV | `§8` | UMV | `§c§l§n` |
| IV | `§9` | UXV | `§4§l§n` |
| LuV | `§d` | MAX | `§f§l§n` |

Жирность и подчёркивание у тиров UV и выше не украшение: без них UV
неотличим от LV, UMV от ULV, UHV от UXV — цвета там повторяются.

Без цвета оставлены 40 тегов: заголовки достижений и квестов имеют
собственную раскраску, а метки конструкций и строки внутри подсказок
подставляются в уже покрашенные строки, где лишний `§r` сбросил бы цвет
остатка.

### Скобки

Квадратные — тир или класс, круглые — состояние:

```
Электрический геологический сканер §d[LuV]§r (Разряжен)
```

### Префиксы материалов

Система `gt.oreprefix.*` уже использовала квадратные скобки, она сохранена:

```
[Слиток] Олово
[Пластина] Сталь
[Длинный стержень] Титан
```

К ней приведено и второе, независимое семейство `prefix.*`, которое раньше
выбивалось из общего вида.

### Аспекты Thaumcraft

Примарные получили собственные чат-коды Thaumcraft: Aer `§e`, Terra `§2`,
Ignis `§c`, Aqua `§3`, Ordo `§7`, Perditio `§8`.

Составные помечены `§5` — штатным цветом выделения Тауманомикона. Это
вынужденное решение: палитра аспектов пастельная, и при сжатии до 16 цветов
чата Potentia `C0FFFF`, Motus `CDCCF4`, Spiritus `EBEBFB` и ещё шесть
превращаются в обычный белый, а Tenebrae `222222` — в чёрный, невидимый на
тёмном фоне.

Аспекты внутри активного `§l` или `§n` не тронуты: цветовой код в Minecraft
сбрасывает форматирование, и жирность потерялась бы до конца строки.

### Вкладки творческого режима

Приведены к виду `Мод: Раздел`:

```
GT: Основное      Forestry: Пчеловодство      BartWorks: Мета-материалы
```

Часть вкладок задаётся кодом модов и языковым файлом не меняется.

## Исправления сверх перевода

Это не опечатки автора базового пака, а расхождения, найденные при сверке с
кодом модов.

### Порядок букв в размерах мультиблоков — 183 строки

В английском `(L x W x H)` — Длина, Ширина, Высота. В паке стояло
`(Ш x В x Д)`: числа те же, буквы переставлены, и подсказка врала, какое
число что означает.

Каждая из 174 правок подтверждена сверкой с `GregTech.lang` по совпадению
ключа: во всех 174 случаях оригинал именно `(L x W x H)`. Ещё в 9 строках
восстановлен потерянный `§7` перед закрывающей скобкой.

Мод **Botanic Horizons не тронут**: там в оригинале действительно
`(W x H x L)`, и русское `(Ш x В x Д)` верно.

### Падежи в сообщениях о сборке — 6 строк

Шаблон подставлял имя предмета в именительном падеже, получалось
«Нет Входной люк [Пар]». Заменено на конструкцию с двоеточием, которая
работает при любом имени:

| было | стало |
|---|---|
| `Нет %s` | `Отсутствует: %s` |
| `Слишком много %s (максимум %s)` | `Слишком много: %s (максимум %s)` |
| `Нужно ровно %s %s` | `Нужно ровно %s: %s` |
| `Тир %s слишком низкий (...)` | `%s: тир слишком низкий (...)` |
| `Недостаточно %s: ...` | `%s: нужно минимум %s, найдено %s` |

### Паровой тир — 6 строк

`Input Bus (Steam)` стоит в оригинале в одном ряду с `Input Bus (ULV)`, то
есть Пар — обозначение тира. Круглые скобки читались как «люк для пара»,
хотя это предметный люк паровой эпохи. Приведено к `[Пар]`.

Жидкостный вход пара называется **Паровой шлюз** и не менялся.

### Тир зарядника GT++

`item.GTPP.BattPack.09.name` был подписан `[MAX]`, а парный ему ключ
`.name.name` — `[UHV]`. В `gregtech-5.09.54.20.jar` в обоих стоит `[UHV]`,
и по порядку тиров после UV идёт UHV. Исправлено.

### Опечатки и смысловые ошибки

| было | стало |
|---|---|
| `Корпус экстримального впуска двигателя` | `экстремального` |
| `Дистилятор` | `Дистиллятор` |
| `[Головка ключ] %s` | `[Головка ключа] %s` |
| `[С средним ...]` (4 строки) | `[Со средним ...]` |
| `[Блок листового] Олово` | `[Блок листового металла] Олово` |
| `Shard of %s` переводился как `%s` | `[Осколок] %s` |
| `[Нанит] %s` (англ. мн. ч.) | `[Наниты] %s` |
| `[Пластина] Дуб` | `[Доска] Дуб` |
| `[Пластина] Стекло` | `[Панель] Стекло` |
| `fallbackBadge=Отступ` | `Запасной` |
| `weather.clear=Очистить` (погода, не действие) | `Ясно` |
| `tile.zaneBlock. (14)` подписан `Zest ⑭` | `Zane ⑭`, как в моде |

## Дефекты апстрима

Обнаружены, но лежат вне перевода — чинить их нужно в самих модах.

- В английской подсказке Большого двигателя сгорания три строки показывают
  сырые ключи вместо названий блоков
  (`gt.blockcasings4.Casing_StableTitanium` и ещё две). В русском варианте
  подставлены настоящие названия, то есть на русском эта подсказка читается
  лучше, чем на английском.
- `fluid.oilgc` и `fluid.fuelgc` в игре показывают ключ вместо названия.
- `prefix.wireFine.name` в оригинале записан как `Fire %s Wire` — опечатка
  вместо `Fine`.
- В GTNH Credits в качестве текста лежит `Lorem ipsum`.
- `Дистилятор` с одной «л» пришёл из русского перевода внутри самого мода
  GregTech.

## Что не переведено и почему

Латиница в 770 строках оставлена осознанно.

| категория | примеры |
|---|---|
| Химические формулы | `ZrCl₄`, `KMg₃(Si₃Al)O₁F₂`, `SiO₂·B₂O₃·Na₂O` |
| Коды материалов | `TPV`, `HSS-G`, `HSS-S`, `MHDCSM` |
| Аббревиатуры | `DTPF`, `RTG`, `NAC`, `TFFT`, `EUT`, `CC`, `VCI`, `VCO` |
| Тиры напряжения | `ULV` … `MAX` — они же в именах предметов |
| Аспекты Thaumcraft | `Aer`, `Terra`, `Aequalitas`, `Vesania`, `Primordium` |
| Реагенты Blood Magic | `Incendium`, `Magicales`, `Sanctus`, `Aether` |
| Латинские биномены | `Saccharomyces cerevisiae`, `Escherichia koli` |
| Названия модов и вкладок | `Applied Energistics 2`, `Open Modular Turrets` |
| Синтаксис команд | `/chunks claim_as <server team> [radius in chunks]` |
| Сигнатуры функций | `clampInt(num, min, max)`, `getField(...)` |
| Авторы и треки пластинок | `Lena Raine - Pigstep` |
| Шаблоны порядка слов | `%SPECIES %TYPE` у Forestry |
| Внутренние заглушки | `NULL`, `_NULL` |

## Обновление под новую версию

Перевод привязан к состоянию строк на указанную дату. При выходе новой
версии GTNH часть ключей появится, часть изменится, часть исчезнет.

1. **Взять новый английский оригинал** из двух источников:
   - `GregTech.lang` из корня `.minecraft` обновлённого инстанса;
   - `assets/<modid>/lang/en_US.lang` внутри джарников модов.

2. **Сравнить множества ключей** с файлами перевода:
   - ключи, которых нет в переводе, — новые, их надо перевести;
   - ключи с изменившимся английским значением требуют пересмотра русского;
   - ключи, исчезнувшие из оригинала, можно удалять.

3. **Держать разметку неизменной:** `%s`, `%d`, `%1$s`, `%%`, `§`-коды,
   литеральные `\n`, `<BR>`, ведущие и концевые пробелы. В подсказках
   мультиблоков отступы структурные, срезать их нельзя.

4. **Сверить результат** по списку из раздела «Автоматическая проверка».
   Расхождение должно быть нулевым.

### Что экономит время

Подсказки мультиблоков собираются из строк, разделённых литеральным `\n`, и
многие сегменты повторяются между машинами дословно. Разбор строки на
сегменты и подстановка уже переведённых даёт около 60 % готового текста без
ручной работы.

### Ловушка при подстановке

Если подставлять уже переведённые имена предметов в перечни блоков
конструкции, туда попадёт цветной тег тира (`§6[MV]§r`), а строка перечня
уже покрашена, и `§r` сбросит её цвет. В таких местах тег должен быть без
цвета:

```
англ:    §620 §fMV Solenoid Superconductor Coil
неверно: §620 §fСоленоидная сверхпроводниковая катушка §6[MV]§r
верно:   §620 §fСоленоидная сверхпроводниковая катушка [MV]
```
